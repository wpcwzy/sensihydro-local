# 协议细节

## 1. DTU（HF5111B）

| 项目 | 值 |
|---|---|
| 角色 | TCP Client（只会主动连服务器） |
| 服务器 | `sensihydro.copeland.cn:5000` |
| 串口 | `19200 8E1` |
| 传输 | 串口上的 **Modbus RTU**；TCP 上是 **Modbus TCP（MBAP）** |
| 心跳 | 连接后周期性发送 `00` + 12 位 MAC（ASCII） |
| 配置方式 | 汉枫 IOTService 协议（UDP 48899 公告 → DTU 回连 48907 → JSON JCMD） |

心跳帧不是 Modbus 帧，bridge 只是原样转发。

## 2. Modbus TCP 帧结构（厂商云 5000 端口）

```
偏移  长度  含义
0     2     事务号 Transaction ID
2     2     协议号 0x0000
4     2     后续长度（单元号 + PDU）
6     1     单元号（本设备恒为 0x01）
7     1     功能码
8     ...   数据
```

常用功能码：

| 功能码 | 含义 | 请求数据 | 响应数据 |
|---|---|---|---|
| `0x03` | 读保持寄存器 | 起始地址(2) + 数量(2) | 字节数(1) + 数据 |
| `0x06` | 写单个寄存器 | 地址(2) + 值(2) | 回显 |
| `0x10` | 写多个寄存器 | 地址(2) + 数量(2) + 字节数(1) + 数据 | 地址 + 数量 |

**单次读最多 20 个寄存器**（超过会超时或异常回包），因此 bridge 按 20 以内分块读。

## 3. 数值编码

所有温度类寄存器使用定点编码：

```
raw = 3000 + ℃ × 100
℃  = (raw - 3000) / 100
```

例：`4800` → 18.00 ℃；`1780` → -12.20 ℃（是的，可以小于 3000）。

其他字段：

| 字段 | 编码 |
|---|---|
| 开关 | `0` / `1` |
| 模式 | `模式号 << 8 | 开关位`（模式号 0–5） |
| 目标温度 | `3000 + ℃ × 100`（0.5 ℃ 步进） |
| 风速 | `0x0100` = 自动；`1`–`10` = 手动档位 |
| 浮球/阀/泵 | `0` / `1` |

模式号：`0` 冷风、`1` 送风、`2` 热风、`3` 地暖、`4` 热+暖（地暖+热风）、`5` 除湿。

## 4. 单元槽位

主控板有 7 个内机槽位（其中 1 个为空），地址按槽位线性排列：

```
状态块： 0x00C8 + 20 × (槽位 - 1)     （20 个寄存器）
控制块： 0x03E8 + 15 × (槽位 - 1)     （4 个寄存器）
```

实测（6 台内机）：

| 内机 | 槽位 | 状态块 | 控制块 |
|---|---|---|---|
| 餐厅 | 1 | `0x00C8` | `0x03E8` |
| 三楼南 | 2 | `0x00DC` | `0x03F7` |
| （空） | 3 | `0x00F0` | `0x0406` |
| 二楼南 | 4 | `0x0104` | `0x0415` |
| 三楼北 | 5 | `0x0118` | `0x0424` |
| 客厅 | 6 | `0x012C` | `0x0433` |
| 二楼北 | 7 | `0x0140` | `0x0442` |

可以用环境变量 `UNITS_FILE` 指定一个 JSON 覆盖该表（名字、槽位、地址），
方便别人适配自己家的房间名/布局，见 `examples/units.example.json`。

## 5. 写入怪癖

实测中遇到的、已经写进实现的坑：

1. **写后生效有延迟**：一般 0.2–1 秒；
2. **连续写太快会被丢**：切模式后立刻写目标温度，温度写常常不生效
   → 实现里在模式写完后等 2 秒，并对目标温度做"写→校验→重试"；
3. **关机状态下写目标温度无效**（控制器忽略）；
4. **主机模式三条写命令需要间隔 2–5 秒**，且顺序必须是"静音 → 节能 → 出水温度设定"；
5. 只有云端才有"定时"：主控板没有可写的本地定时寄存器，定时需求请用 HA 自动化。

## 6. 事务号与注入

bridge 注入自己请求时使用 `0x8000`–`0x8FFF` 段的事务号：

- 发出去的注入帧的响应会被 bridge 拦截，**不会**回传给厂商云；
- 云端自己的请求（事务号随机/递增）及其响应原样透传；
- 注入请求串行执行，避免 RS485 上出现交错的读取。

## 7. 心跳与断线

- DTU 每几秒发一次 `00<MAC>` 心跳（非 Modbus）；
- bridge 侧断线后 DTU 会自动重连（几秒到几十秒）；
- 如果想强制让 DTU 重新解析域名，用 `tools/dtu_reload.py` 发 JCMD `reload`，
  或者给空调主控板断电重启。

## 8. 抓包与调试建议

- bridge 自带 `/api/read`、`/api/write` 两个调试接口，可以直接读写任意寄存器；
- 打开 `LOG_LEVEL=DEBUG` 可以看到每一帧的事务号/功能码/地址；
- 排查时先确认 `/health` 的 `dtu_connected`/`cloud_connected`，再看 `injected_requests` 是否增长。
